=== 【3】关键发现（可写入报告）===
1. 完整访问路径：启动页 → 登录页 → 目的地列表 → 目的地详情(北京) →
   攻略详情(北京三日游) → 返回列表 → 搜索页 → 搜索结果(上海) →
   目的地详情(上海) → 返回列表 → 退出
2. 用户行为类型覆盖：APP_START / LOGIN / PAGE_ENTER / CLICK /
   LIKE / SEARCH / SHARE / APP_EXIT，共 8 种
3. 涉及页面：启动页、登录页、目的地列表、目的地详情、攻略详情、
   搜索页、搜索结果页、主页，共 8 类页面
4. 后端通过 sessionId 将同一会话内的行为串联为有序访问路径，
   /api/behavior/session/{sessionId} 接口返回 pageSequence 字段
   可直接用于漏斗分析、用户路径分析、页面停留分析。

附：本次修复的后端缺陷
  UserBehaviorController.recordBehavior() 原先强制使用 HTTP request 的
  session id（request.getSession().getId()），导致 App 端上报的 sessionId
  被丢弃、每个请求都被当作独立会话。已修复为优先使用客户端上报的
  sessionId，使会话内的页面访问顺序得以正确聚合。
